ВЕСОВОЙ ДОЗАТОР САХАРА В МЕШКИ 25/50 КГ — ПРОЕКТ «ЛИВНЫ»
Платформа: ОВЕН СПК107 · CODESYS 3.5.17 · IEC 61131-3 (Structured Text)
=============================================================================

СОСТАВ ПРОЕКТА (порядок добавления в CODESYS):
  01_DUT_Types.st        — DUT: перечисления и структуры данных
  02_GVL_Global.st       — GVL: глобальные переменные
  03_FB_InputHandler.st  — ФБ: антидребезг входов МВ110-8Д.4Р, фронты кнопок
  04_FB_WeightChannel.st — ФБ: фильтр, стабильность, тара, скорость потока
  05_FB_DoserControl.st  — ФБ: автомат дозирования (ядро)
  06_FB_AlarmManager.st  — ФБ: аварии с самоблокировкой, мигалка 1 Гц
  07_PRG_Main.st         — PRG: главный контур управления
  08_PRG_HMI.st          — PRG: сервис экрана СПК107 (рецепты, статистика)

ПОДКЛЮЧЕНИЕ БИБЛИОТЕК И ШАБЛОНОВ ОВЕН:
  1. Установить CODESYS 3.5.17 с target-пакетом ОВЕН СПК107.
  2. Менеджер библиотек → добавить библиотеку шаблонов модулей МХ110
     (поставляется с Owen Configurator / СПК-пакетом, см. owen.ru —
     «Шаблоны модулей МХ110 для CODESYS 3.5»).
  3. В задачу добавить ФБ-шаблоны:
       Mv110Td      — для МВ110-224.1ТД  (адрес 16, порт COM2, 115200 8N1)
       Mv110_8D4R   — для МВ110-8Д.4Р    (адрес 17, тот же порт)
  4. Связать шаблон тензомодуля с GVL (см. ниже). В шаблоне МВ110-224.1ТД
     настроить: тип датчика (2/4 мВ/В), число проводов (4 или 6),
     единицы — кг, цифровой фильтр модуля 5…10 Гц.

СВЯЗЫВАНИЕ ПЕРЕМЕННЫХ (делается интегратором в CODESYS):

  Выходы шаблона Mv110Td            →  GVL
  ────────────────────────────────     ───────────────────────
  значение веса (REAL, кг)          →  g_rWeightRaw
  признак корректных данных         →  g_xWeightValid
  признак ошибки модуля             →  g_xWeightErr
  вход «тара/установка нуля»        ←  g_xTareToModule

  Входы/выходы шаблона Mv110_8D4R   →  GVL
  ────────────────────────────────     ───────────────────────
  DI0 … DI7                         →  g_xDiStart … g_xDiCoverClosed
  DO0 … DO3 (реле R0…R3)            ←  g_xDoClamp, g_xDoCoarse,
                                       g_xDoFine, g_xDoSignal

  НАЗНАЧЕНИЕ КАНАЛОВ (см. комментарии в 02_GVL_Global.st):
    DI0 Пуск · DI1 Стоп · DI2 Аварийный стоп (НЗ!) · DI3 Мешок в зоне
    DI4 Концевик зажима · DI5 Реле давления воздуха · DI6 Уровень бункера
    DI7 Защитная крышка
    R0 Зажим · R1 Грубый шнек · R2 Точный шнек · R3 Лампа/зуммер

  Экран СПК107: объекты визуализации привязываются к g_Hmi.*, g_xHmi*,
  g_Manual.*, g_rHmiSetpoint, g_xManualMode.

ЗАДАЧИ:
  Основная задача: PRG_Main (цикл 20 мс) и PRG_HMI (цикл 50…100 мс).

ПУСКОНАЛАДКА (кратко):
  1. Режим РУЧНОЙ: проверить каждое реле и каждый вход по очереди.
  2. Калибровка весов: ноль (пустая платформа) → гиря/мешок известного
     веса → записать калибровку в МВ110-224.1ТД (Owen Configurator).
  3. Подбор rCoarseCutoff (обычно 8…12 % дозы) и rInFlightInit (0.1…0.3 кг);
     адаптация rLearnGain=0.3 сделает остальное за 10…20 циклов.
  4. Допуски: технологический допуск ±50 г на 25 кг (0,2 %) — жёстче
     ГОСТ 8.579-2002 (±1 % для 15–50 кг). Поле rTolerancePlus/Minus = 0.050.
  5. Прогнать 10 циклов, проверить статистику (g_Stats) и тренд rInFlight.

ОСОБЕННОСТИ АЛГОРИТМА (подробно — в шапке 05_FB_DoserControl.st):
  двухступенчатая подача; отсечка «на лету» с адаптацией Δ_лету по ошибке
  каждой дозы; контроль потока (защита от затора шнека); досыпка при
  недовесе (до 3 попыток); передоз — авария с ручной выгрузкой;
  аварийный стоп и потеря связи с весами гасят выходы в том же скане.
